# M13.4 Hosted Pricing Service Deployment on Render with PLATFORM_PRICE_KEY (#104, #173)

## Architecture Overview

The Price Optimization Model serves dual integration roles:
1. **Protected Mobile Client Gateway:** `POST /api/v1/optimize-price` protected by Firebase ID Bearer tokens, mapped to verified Firebase Auth UIDs and backed by Google Cloud Firestore (`src/api/deployment.py`).
2. **Career Mentor OS Platform Adapter Contract (#99):** `POST /price` authenticated via `PLATFORM_PRICE_KEY` and the `X-Platform-Key` header, delivering `{ min, max, comparables, reason }` to the external platform staging adapter (`src/api/hosted.py`).

`M13.4` provides the production deployment infrastructure for hosting the service on **Render** (https://render.com), fulfilling the Career Mentor OS platform contract with automated mentor resolution and health auditing.

```text
[Career Mentor OS Platform]
           |
           | HTTP POST /price
           | Headers: X-Platform-Key: $PLATFORM_PRICE_KEY
           | Body: {"mentorId": "p1"}
           v
[Render Hosted Web Service]
     ├── Uvicorn on 0.0.0.0:$PORT
     ├── src.api.hosted:app
     ├── Pinned Manifest & P2P Tariff Validation
     ├── Auto-seeded Repository (platform_mentor_corpus)
     │     └── Resolves "p1" / "u1" -> description, industry, KE country
     └── 53D Hybrid KD-Tree + IDW Engine + M-Pesa Tariff Surcharge
           │
           v
     Returns {"min": ..., "max": ..., "comparables": [...], "reason": "..."}
```

## Render Infrastructure-as-Code (`render.yaml`)

The service is configured declaratively using Render's Blueprint specification at `render.yaml` with a containerized Docker runtime:

```yaml
services:
  - type: web
    name: price-optimization-service
    env: docker
    region: oregon
    plan: starter
    dockerfilePath: ./Dockerfile
    dockerContext: .
    dockerCommand: uvicorn src.api.hosted:app --host 0.0.0.0 --port $PORT
    healthCheckPath: /health
    autoDeploy: true
    envVars:
      - key: PYTHONUNBUFFERED
        value: "1"
      - key: PYTHONDONTWRITEBYTECODE
        value: "1"
      - key: NLTK_DATA
        value: /usr/local/nltk_data
      - key: PRICING_ARTIFACT_DIR
        value: artifacts
      - key: PRICING_TARIFF_CSV
        value: config/tariffs/mpesa_p2p_users_2026-08-04.csv
      - key: PRICING_TARIFF_SHA256
        value: 4390d9d5ec920c68000da8562c140e7477a0afac22ad41c8a2fa23227761e882
      - key: PRICING_ARTIFACT_MANIFEST_SHA256
        value: 568edb5c088564fd637de052d51eeaa902ab6c759d29eb10251fdc6880920226
      - key: SEED_PLATFORM_MENTORS
        value: "true"
      - key: PLATFORM_PRICE_KEY
        sync: false

        value: src.api.hosted:app
```

## Deployment Options on Render

Render supports two deployment methods for this containerized service:

### Option A: Render Blueprint (Recommended)
1. In the Render Dashboard, select **New -> Blueprint** and connect the repository.
2. Render automatically discovers `render.yaml`, configures the Docker runtime, context, health checks, and environment variables.
3. Supply secret values (e.g. `PLATFORM_PRICE_KEY`) when prompted.

### Option B: Web Service via Dockerfile
1. In the Render Dashboard, select **New -> Web Service**.
2. Connect your Git repository (GitHub / GitLab).
3. Select **Docker** as the runtime (Render will build directly from `Dockerfile`).
4. Ensure the port setting uses the default `10000` or relies on the dynamic `$PORT` injected by Render.
5. In **Advanced**, add the environment variables defined above (`PLATFORM_PRICE_KEY`, `PRICING_TARIFF_SHA256`, etc.). Render sets `RENDER=true` automatically, which configures the container to execute `src.api.hosted:app`.

## Deployment Steps on Render

1. **Connect GitHub Repository:**
   In the Render Dashboard, select **New -> Blueprint** and connect the repository. Render automatically discovers `render.yaml`.
2. **Configure Secret Environment Variables:**
   Under the service settings, supply the secret `PLATFORM_PRICE_KEY` value agreed upon with the Career Mentor OS platform team.
3. **Deploy & Verify:**
   - Health Probe: `GET https://<service-name>.onrender.com/health` returns status `200` with `HEALTHY`.
   - Readiness Probe: `GET https://<service-name>.onrender.com/ready` returns `200` confirming pinned model artifacts and tariffs are loaded.
   - Platform Verification:
     ```bash
     curl -X POST "https://<service-name>.onrender.com/price" \
          -H "Content-Type: application/json" \
          -H "X-Platform-Key: $PLATFORM_PRICE_KEY" \
          -d '{"mentorId": "p1"}'
     ```
     Expected response shape:
     ```json
     {
       "min": 4200.0,
       "max": 5100.0,
       "comparables": [
         {"peer_index": 3, "rate": 4200.0, "similarity": 0.91},
         {"peer_index": 7, "rate": 5100.0, "similarity": 0.80}
       ],
       "reason": "Weighted from 2 comparable peers to 4757.00 KES including a 57.00 KES M-Pesa surcharge."
     }
     ```

## Security & Operational Controls

- **Fail-Closed Gate:** If `PLATFORM_PRICE_KEY` is not configured, `POST /price` returns `503 Service Unavailable`, preventing unauthenticated pricing.
- **Constant-Time Comparison:** Key verification uses `hmac.compare_digest` to prevent timing attacks.
- **Port Autodiscovery:** The entrypoint respects Render's dynamic `$PORT` environment variable.
- **Artifact Immutability:** Independent SHA-256 verification prevents running unapproved model bundles or tampered tariff schedules.

## Android Client Integration

The native Android app (`app/`) connects to this deployed web service via Retrofit when live backend mode is toggled:
- Set `useLiveBackend=true` (or `USE_LIVE_BACKEND=true`)
- Set `pricingApiBaseUrl=https://<service-name>.onrender.com/` (or `PRICING_API_BASE_URL`)
- Client calls `POST /api/v1/optimize-price` with Firebase ID bearer tokens and polls `GET /health` for service health.
- Client `OkHttpClient` is configured with extended 30s connection and 60s call timeouts to gracefully tolerate Render Free instance wake-up cold starts.
