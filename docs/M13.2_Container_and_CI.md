# M13.2 protected API container and integration gates (#77)

The image runs Python 3.11-slim, `src.deployment:app` on port 8000 as an unprivileged user. Its allowlisted build context includes **only** `src/*.py`, `requirements.txt` and `Dockerfile`: no model binaries, dataset, tariff CSV, tests, ADC file or service-account key is shipped. The older `src.serve:app` is a **local legacy app without pricing authentication**; never deploy that entrypoint. This work does not implement mentor UID binding (#69), camelCase DTOs (#83), asynchronous audit (#72), or the Android module (#74-#76).

## Artifact and secret provisioning

1. Generate a full versioned model export **outside Git**, validate its provenance and `inference_config.json` schema, and record a SHA-256 digest for each file in your release management system. Publish an immutable bundle and mount its **entire** contents read-only at `/opt/pricing/artifacts`. Never trust third-party joblib files (deserialization executes code); only load internally approved builds. The historical stratified evaluation is exploratory proxy-budget evidence, not validated mentor pricing. Empirical chronological OOT/R² gating is deferred under #91; it is not a deployment prerequisite.
2. Provide the approved M-Pesa schedule read-only at `/opt/pricing/tariff.csv`. The repository test fixture is for local/CI smoke checks only, not a regulatory tariff source.
3. Create a Firebase project with Authentication (ID tokens) and Firestore enabled, deploy least-privilege runtime ADC (Workload Identity preferred, or a secret-file mount with restricted permissions). Set `FIREBASE_PROJECT_ID` to the project whose ID tokens should be verified. Firebase credentials are supplied via the hosting platform, **not** a build arg, image layer, GitHub secret printed in logs, or `.env.example`. Set `GOOGLE_APPLICATION_CREDENTIALS` only when a runtime secret file is used. Configure Firestore IAM/rules for the account, monitoring, TLS ingress and secure token acquisition independently.
4. Optionally override paths using `PRICING_ARTIFACT_DIR` and `PRICING_TARIFF_CSV` (see `.env.example`). Never place credentials in this example. The app refuses to start without `FIREBASE_PROJECT_ID` or working Admin/Firestore initialization; it never silently switches to an in-memory repository. Host-level and cluster credentials are not tested by fixture CI.

PowerShell example after approving local artifacts, tariff and a **development** ADC secret:

```powershell
docker build -t pricing-api:local .
Copy-Item .env.example .env  # replace the placeholder project ID in .env before running
$artifacts = (Resolve-Path .\artifacts).Path
$tariff = (Resolve-Path .\tests\fixtures\raw\Mpesa_Tarrifs\tarrifs_full_schedule.csv).Path
$adc = (Resolve-Path .\local-service-account.json).Path  # outside Git; omit mount if platform supplies ADC
docker run --rm -p 8000:8000 --env-file .env -e GOOGLE_APPLICATION_CREDENTIALS=/run/secrets/firebase.json `
  --mount "type=bind,source=$artifacts,target=/opt/pricing/artifacts,readonly" `
  --mount "type=bind,source=$tariff,target=/opt/pricing/tariff.csv,readonly" `
  --mount "type=bind,source=$adc,target=/run/secrets/firebase.json,readonly" pricing-api:local
```

Replace the placeholder project ID in a **local untracked** `.env` (not the checked-in example) before running; the fixture tariff in the command is for smoke tests only. On native cloud deployments, use platform-managed secret injection instead of a service-account file. Bind volumes read-only; use checksums to detect replacement of the approved bundle. Create a fresh image/release for each change; never mutate a live artifact mount in place.

`GET /health` is diagnostic: it reports loaded model state and configured repository type. `GET /ready` responds 200 only if the artifact set loads and a bounded Firestore read succeeds; otherwise 503. The protected route rejects missing/malformed/invalid Firebase bearer ID tokens with 401, missing/incompatible artifacts with 503, and does not return a successful response if its audit append fails. The legacy snake_case payload is still in use; once #83 adds `mentorId`, #69 must bind it to the authenticated UID before any request proceeds. Firestore emulator/project setup for CI requires Firebase CLI and a disposable project namespace; **do not** reuse real credentials or production project IDs in integration tests.

## CI and measurement status

`Python Sanity` keeps the historical pytest suite. `Protected Pricing Integration` verifies 401/422, quote invariants, fake Firestore append and unready states without production credentials. `Container Build` builds and inspects the image allowlist and checks that startup fails **specifically** when Firebase project configuration is missing. This is not an end-to-end live Firebase/container acceptance test: a verified request with approved mounted artifacts, real ADC and a real Firestore project still requires a controlled staging deployment. A fixture test warms both the in-process inference and `TestClient` HTTP path, then prints average ms across 5 requests; it measures neither a real network RTT nor a warmed production container, nor simulated 3G (M14). Use this exact test with `python -m pytest tests/test_container_gateway.py -q -s` for comparable **local fixture** timings; do not infer a latency SLA from 5 samples.

`Android Build and Tests` logs a notice while neither wrapper nor module exists (#74/#76); it fails if only one exists and builds/tests the module once both exist. A green job **before the module lands does not mean Android was tested**. Firebase/Firestore integration uses local fakes, not the Firebase emulators; add emulator-backed coverage when #69/#75 and the client are available. The synthetic `tests/test_oot_gate.py` tests only reject malformed reports; there is no empirical OOT CI job because #91 defers that research. Do not use fabricated or stratified R² values to claim empirical pricing quality. Keep this PR Draft until all checks for this branch pass; completing the full mobile-cloud staging demonstration still depends on upstream issues and real deployment configuration.
