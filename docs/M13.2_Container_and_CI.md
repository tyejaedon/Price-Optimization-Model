# M13.2 protected API container and integration gates (#77)

The image runs Python 3.11-slim, `src.deployment:app` on port 8000 as an unprivileged user. Its allowlisted build context includes **only** `src/*.py`, `requirements.txt` and `Dockerfile`: no model binaries, dataset, tariff CSV, tests, ADC file or service-account key is shipped. The older `src.serve:app` is a **local legacy app without pricing authentication**; never deploy that entrypoint. #77 did not implement mentor UID binding (added in #69), camelCase DTOs (#83), asynchronous audit (#72), or the Android module (#74-#76).

## Artifact and secret provisioning

1. Generate a complete model export **outside Git** using `python -m src.train_pipeline --mode evaluate ... --no-enforce-quality-gate` for a proxy-data demo. Review its data source, `inference_config.json`, `artifact_manifest.json`, model files and actual evaluation. The manifest specifies 53D feature/preprocessing schema, IDW k/epsilon/weights, partition fallback, dataset checksum/source/split and `exploratory_not_empirically_approved`. Record the **manifest's SHA-256 independently in trusted release configuration** as `PRICING_ARTIFACT_MANIFEST_SHA256` (64 lowercase hex chars). The service verifies that pin and every listed file **before** joblib.load; it never trusts checksums supplied only by a mounted bundle. Publish an immutable bundle and mount its entire contents read-only at `/opt/pricing/artifacts`. Never compute the trusted pin from an unknown download or wrap old joblib with a freshly created manifest: deserialization can execute code. Old unsigned/incompatible exports must be retrained/re-exported internally. Historical stratified evaluation is exploratory proxy-budget evidence, not validated mentor pricing; empirical chronological OOT/R² gating is deferred under #91 and is not a demo prerequisite.
2. Provide the approved M-Pesa schedule read-only at `/opt/pricing/tariff.csv`. The repository test fixture is for local/CI smoke checks only, not a regulatory tariff source.
3. Create a Firebase project with Authentication (ID tokens) and Firestore enabled, deploy least-privilege runtime ADC (Workload Identity preferred, or a secret-file mount with restricted permissions). Set `FIREBASE_PROJECT_ID` to the project whose ID tokens should be verified. Firebase credentials are supplied via the hosting platform, **not** a build arg, image layer, GitHub secret printed in logs, or `.env.example`. Set `GOOGLE_APPLICATION_CREDENTIALS` only when a runtime secret file is used. Do not set `FIREBASE_AUTH_EMULATOR_HOST` or `FIRESTORE_EMULATOR_HOST`: the protected entrypoint rejects emulator mode at startup. Configure Firestore IAM/rules for the account, monitoring, TLS ingress and secure token acquisition independently.
4. Configure the externally pinned manifest digest along with optional `PRICING_ARTIFACT_DIR` and `PRICING_TARIFF_CSV` (see `.env.example`). Never place credentials in this example. The app refuses to start without `FIREBASE_PROJECT_ID` or working Admin/Firestore initialization; with an invalid/missing digest the API reports unready, never loading model pickles or switching to an in-memory repository. Host-level and cluster credentials are not tested by fixture CI.

PowerShell example after approving local artifacts, tariff and a **development** ADC secret:

```powershell
docker build -t pricing-api:local .
Copy-Item .env.example .env  # replace the placeholder project ID in .env before running
$digest = (Get-FileHash .\artifacts\artifact_manifest.json -Algorithm SHA256).Hash.ToLowerInvariant() # ONLY your own reviewed local export
# Put PRICING_ARTIFACT_MANIFEST_SHA256=$digest in the untracked .env; use an independently reviewed release digest in deployment.
$artifacts = (Resolve-Path .\artifacts).Path
$tariff = (Resolve-Path .\tests\fixtures\raw\Mpesa_Tarrifs\tarrifs_full_schedule.csv).Path
$adc = (Resolve-Path .\local-service-account.json).Path  # outside Git; omit mount if platform supplies ADC
docker run --rm -p 8000:8000 --env-file .env -e GOOGLE_APPLICATION_CREDENTIALS=/run/secrets/firebase.json `
  --mount "type=bind,source=$artifacts,target=/opt/pricing/artifacts,readonly" `
  --mount "type=bind,source=$tariff,target=/opt/pricing/tariff.csv,readonly" `
  --mount "type=bind,source=$adc,target=/run/secrets/firebase.json,readonly" pricing-api:local
```

Replace the placeholder project ID in a **local untracked** `.env` (not the checked-in example) before running; the fixture tariff in the command is for smoke tests only. On native cloud deployments, use platform-managed secret injection instead of a service-account file. Bind volumes read-only; use checksums to detect replacement of the approved bundle. Create a fresh image/release for each change; never mutate a live artifact mount in place.

`GET /health` reports model/database state, artifact manifest version/digest prefix, dataset version, proxy source, exploratory status and sanitized failure reason (never text, tokens, dataset paths or rates). `GET /ready` responds 200 only if the pinned, compatible artifact set loads and a bounded Firestore read succeeds; otherwise 503 with a reason unrelated to empirical R². The protected route rejects missing/malformed/invalid/expired Firebase bearer ID tokens with 401, a missing or mismatched `mentorId` with 403, and missing/incompatible artifacts with 503; none of these auth failures runs inference or appends an audit record. Successful protected audits include the authorized `mentor_id`; audit append failure still blocks success. The legacy snake_case payload remains in use, with optional `mentorId` for local callers but **required `mentorId` equal to the verified UID** for deployed pricing. Other mentor identifiers need a separately implemented owner mapping (#84); #83 owns the full camelCase migration. Tests inject a fake verifier without credentials or emulator mode; future emulator/project integration tests need a separate local-only setup and disposable namespace, **not** the protected deployment entrypoint or real credentials.

## CI and measurement status

`Python Sanity` keeps the historical pytest suite. `tests/test_artifact_contract.py` checks synthetic offline/online coordinates, saved nondefault k=2, partition fallback, hashes/schema, and an already-warmed API call; it asserts no wall-clock threshold. `Protected Pricing Integration` verifies 401/422, quote invariants, fake Firestore append and unready states without production credentials. `Container Build` builds and inspects the image allowlist and checks that startup fails **specifically** when Firebase project configuration is missing. This is not an end-to-end live Firebase/container acceptance test: a verified request with approved mounted artifacts, real ADC and a real Firestore project still requires a controlled staging deployment. A fixture test warms both the in-process inference and `TestClient` HTTP path, then prints average ms across 5 requests; it measures neither a real network RTT nor a warmed production container, nor simulated 3G (M14). Use `python -m pytest tests/test_container_gateway.py -q -s` for comparable **local fixture** timings; #70 owns representative preload/P95 profiling and any performance gate. Do not infer a latency SLA from 5 samples.

`Android Build and Tests` logs a notice while neither wrapper nor module exists (#74/#76); it fails if only one exists and builds/tests the module once both exist. A green job **before the module lands does not mean Android was tested**. Firebase/Firestore integration uses local fakes, not the Firebase emulators; add separately isolated emulator-backed coverage when #75 and the client are available. The synthetic `tests/test_oot_gate.py` tests only reject malformed reports; there is no empirical OOT CI job because #91 defers that research. Do not use fabricated or stratified R² values to claim empirical pricing quality. Keep this PR Draft until all checks for this branch pass; completing the full mobile-cloud staging demonstration still depends on upstream issues and real deployment configuration.
