# M8.2 Inference Latency and Operational Stability

M8.2 provides a repeatable performance profile for the pricing inference path. The
profile is intentionally independent of Firestore and service-account credentials:
local runs use deterministic in-process model components, while a running M7.2
HTTP endpoint can be measured through an explicit URL.

## Measurements

The profiler records the following for each operation:

- request count and failed-call count;
- mean, minimum, P50, P95, P99, and maximum latency in milliseconds;
- successful-request throughput;
- exception type counts;
- Python allocation growth during a sequential run.

The measured operations are:

- `nlp_transform`: TF-IDF/SVD query transformation;
- `spatial_idw_prediction`: KD-Tree search and IDW peer prediction;
- `in_process_inference`: text transform, 53-D fusion, IDW prediction, and tariff quote;
- `http_inference`: optional POST probe for a running M7.2 service.

Memory stability uses Python `tracemalloc`. It detects obvious Python-level
allocation growth; it is not a replacement for process RSS/container metrics.

## Operational gates

The default profile evaluates:

- P95 latency at or below `250 ms` for NLP, spatial, and end-to-end operations;
- zero inference failures;
- no more than `1,000,000` bytes of traced allocation growth across 1,000 sequential
  in-process calls.

These are configurable measurement thresholds, not claims about an HTTP deployment
that has not been started. A failed gate is recorded in the report so the result can
be investigated rather than hidden.

## Local reproducibility

From the repository root:

```powershell
python -m src.performance_profiling `
  --output-dir reports/inference_latency `
  --iterations 100 `
  --memory-iterations 1000 `
  --warmup-iterations 10 `
  --target-p95-ms 250 `
  --max-memory-growth-bytes 1000000
```

The command writes:

```text
reports/inference_latency/inference_latency_profile.json
reports/inference_latency/inference_latency_profile.md
```

The generated `reports/` directory is intentionally excluded from version control.

## Optional HTTP endpoint probe

When M7.2 is running locally, profile its JSON endpoint without importing its
application or accessing its credentials:

```powershell
python -m src.performance_profiling `
  --endpoint-url http://127.0.0.1:8000/api/v1/optimize-price `
  --output-dir reports/inference_latency_http `
  --iterations 100 `
  --memory-iterations 1000
```

The HTTP probe sends the documented pricing request shape and reports the response
latency and HTTP failures separately from the local component timings.

## Interpretation

A passing local profile demonstrates that the current component pipeline is
repeatable and does not show obvious Python-level growth under the configured test.
It does not establish production capacity, Firestore latency, network behavior, or
multi-worker RSS stability. Those require deployment-level load tests and should be
run after M7.2 is available.
