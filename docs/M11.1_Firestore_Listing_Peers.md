# M11.1 (#71): mentor ownership and root listing peers

## Document contracts

- `/mentors/{mentor_id}` contains `auth_uid` (the authorized Firebase Auth UID), `country_code` (ISO-2), `account_status`, `full_name`, `email` and optional admin metadata. Its path ID is stable and **may differ** from the UID. Only trusted/admin writers can bind an `auth_uid`; an existing binding cannot be reassigned via upsert. Protected pricing reads this document using the token's verified UID and checks owner, active status and country before inference. Missing and unauthorized mentors fail without an audit or a cross-account fallback. Absent `auth_uid` on a legacy profile does **not** authorize a token by coincidental path-ID equality. #84 owns future request hydration.
- `/service_listings/{listing_id}` is a **root collection**, not `/mentors/{mentor_id}/service_listings`. `listing_id` is the immutable Firestore document ID, `mentor_id` is a parent document lookup key, `industry_id` a supported engine partition, `title` public job title, `raw_description` published 20–2000-character listing text, `latent_svd_vector` a native array of exactly 50 finite Python floats, `verified_rate` a finite positive KES/hour source-approved peer rate, and `is_active` a boolean. Listing upserts replace the document (to avoid stale fields), require an existing parent mentor and cannot reassign its `mentor_id`. The 50D vector is produced by the **same released** fitted TF-IDF/SVD reducer; it is not a 53D fused vector, a JSON string, or a distance-search feature computed by Firestore.
- `get_mentor(mentor_id, verified_uid)` and `get_listing(listing_id)` return `None` for missing documents; invalid IDs and unauthorized reads raise an error. Firestore connectivity errors must not be interpreted as missing documents. The pricing KD-tree stays in memory, not a Firestore join or per-request collection scan. Repository APIs are trusted service boundaries, **not** public unauthenticated listing write endpoints.

## Stable source and release/refresh procedure

1. Provision mentor documents with an independently verified Firebase owner UID. Obtain listing IDs from the platform's **actual root listing document IDs** and rates from a genuinely approved/verified KES/hour source; the current marketplace job budgets and platform mentor asking rates are *proxies*, not verified listings. Do not synthesize listing IDs from `record_id`, row positions, mentor profile IDs or job titles. If a genuine listing source is unavailable, leave `listing_id` null and return no comparable for that peer.
2. Build a versioned local harmonized parquet outside Git with optional `listing_id` and `job_title` columns for truly corresponding rows. Preserve the same exact `raw_description`, partition (`industry_partition` = `industry_id`), title and KES/hour target used to produce the root listing. Duplicate or bogus IDs, inactive/missing documents, and mismatched rates/text/partitions/titles/vectors block export. Rows without IDs may train as proxy peers, but they must never be represented as listing-backed comparables.
3. Fit the NLP pipeline using training rows only and calculate each listing's native 50-float vector with the release's fitted reducer. Publish or refresh the matching root listing documents using `Repository.upsert_listing` from a trusted offline/admin process; do not copy raw private mentor profiles into the listing. Rebuild with the **same immutable dataset and split/reducer settings** after publication; export compares every stored listed vector to that newly fitted reducer (absolute tolerance `1e-6`) and refuses stale vectors. For a Firestore-backed export, run `python -m src.train_pipeline --mode evaluate --harmonized-parquet <local.parquet> --macro-lookup <local.json> --artifact-dir <new-export> --no-enforce-quality-gate --verify-listings-firestore` with Application Default Credentials provided outside this repo. Library callers can inject an `InMemoryRepository` or `FirestoreRepository(client=fake)` as `listing_repository`; no cloud is needed for tests. OOT export supports the same verification when its separate research gate is applicable.
4. Check every active listing-backed training row against root Firestore documents before allowing a release. The verified ID and title are serialized alongside each peer's *own* index, rate and coordinate in `industry_kdtrees.joblib` and bound to the versioned artifact manifest. Keep that immutable snapshot and the listing collection in sync at deployment: if a listing is edited, inactivated or its approved rate changes, rebuild/reverify the index and publish a newly pinned artifact set, or remove its comparable provenance; do not reuse stale IDs. The service does not hit Firestore on each KD-tree match, and cannot assert live listing freshness after deployment. Existing artifacts lacking provenance remain valid but yield no listing-backed comparables. `kNeighborsUsed` still counts *all* matched index peers; only verified listing-backed peers enter canonical `comparables`. Confidence remains uncalibrated.

Only privileged service accounts should read mentor PII or write listings; clients cannot scan root listings or access mentors by arbitrary path. Publish only consented listing text/titles. Never store bearer tokens, credentials, private profile text, or datasets in root listings/artifacts/commits. Keep inputs under ignored `data/` and artifacts outside version control. This release procedure is an engineering contract, **not** evidence that proxy marketplace labels are verified mentor earnings (#91).
