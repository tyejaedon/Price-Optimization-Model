# M11.4 Hydrate Missing Pricing Profile Fields (#84)

## Scope and Goal

Implements **FR-01 profile hydration** for authenticated pricing requests (`POST /api/v1/optimize-price`) when optional capability descriptions (`rawText` / `raw_description`) or pricing metadata (`mentorCountry` / `mentor_country`, `costOfLivingIndex` / `cost_of_living_index`, `industry` / `selected_industry`) are omitted from the request payload.

Unauthenticated local requests remain supported for offline development but cannot perform profile hydration without an authenticated UID binding; incomplete unauthenticated requests continue to fail closed with HTTP 422.

## Authorization and Security Boundary

1. **Token Verification Precedence**: Profile hydration occurs exclusively on authenticated routes where a verified Firebase UID is extracted by the gateway (`TokenVerificationService` / `token_verifier`).
2. **Authorized Mentor Resolution**: The gateway resolves `/mentors/{mentor_id}` via `Repository.get_mentor(mentor_id, verified_uid)`. The document's stored `auth_uid` must match the caller's verified UID. The request's body `mentorId` is never trusted in isolation as an identity credential.
3. **Account Status Verification**: The mentor's `account_status` must equal `"active"`. Inactive, missing, or unauthorized mentors return HTTP 403 (`"mentor authorization required"`) without executing inference or scheduling quote audits.
4. **Cross-Account Isolation**: If a caller provides a specific `listingId`, the service verifies that `/service_listings/{listing_id}.mentor_id` equals the authorized `mentor_id`. An unauthorized listing yields HTTP 403 (`"listing does not belong to authorized mentor"`), strictly preventing identity crossover.

## Hydration Rules and Data Precedence

### 1. Country Code (`mentorCountry` / `mentor_country`)

- **Explicit Request Value**: If provided, `mentorCountry` must match the verified mentor's `country_code` exactly. A mismatch raises HTTP 422 (`"mentorCountry must match verified mentor country"`).
- **Hydrated Value**: If omitted from the request, `mentorCountry` is hydrated from `/mentors/{mentor_id}.country_code`. The country code must be a valid 2-letter ASCII code (normalized to uppercase ISO-2); missing or malformed country codes fail with HTTP 422 (`"missing or invalid verified mentor country code"`).

### 2. Cost of Living Index (`costOfLivingIndex` / `cost_of_living_index`)

- **Explicit Override**: If provided in the request body, the caller's value takes precedence over any stored Firestore attribute.
- **Hydrated Value**: If omitted from the request, the field is hydrated from `/mentors/{mentor_id}.cost_of_living_index` if present.
- **Bounds Validation**: Stored or provided cost-of-living values must be finite numbers within `0.01 <= cost_of_living_index <= 1000.0`. Invalid values fail with HTTP 422 (`"invalid cost_of_living_index on mentor profile"`).
- **Default Fallback**: If absent from both request and mentor profile, the field remains `None`, and the inference normalizer safely falls back to the bundled macro lookup table.

### 3. Capability Description (`rawText` / `raw_description`)

- **Explicit Request Value**: If supplied in the request body, it is validated against the 20–2000 character contract and used directly for feature extraction.
- **Targeted Listing Hydration (`listingId` supplied)**:
  - Looks up root `/service_listings/{listing_id}`.
  - Verifies listing exists (HTTP 422 if missing), belongs to the authorized mentor (HTTP 403 if mismatched), and is active (HTTP 422 if inactive).
  - Validates industry compatibility with the request's partition.
  - Hydrates `rawText` from `listing.raw_description`, enforcing the 20–2000 character length bounds.
  - Hydrates optional `market_competitiveness` and `base_rate_floor` if omitted from the request.
- **Deterministic Listing Selection (`listingId` omitted)**:
  - Queries active root listings linked to the mentor via `Repository.list_listings_for_mentor(mentor_id)`.
  - Filters active listings matching the requested industry partition.
  - **Deterministic selection rule**: Active matching listings are sorted alphabetically by their immutable document ID (`listing_id` ascending). The first matching listing is deterministically selected.
  - If no active listings exist in the requested industry, attempts hydration from documented mentor profile text (`/mentors/{mentor_id}.raw_description`).
  - If description text cannot be found or violates the 20–2000 character length contract, fails with HTTP 422 (`"rawText is required and could not be hydrated from mentor profile or active listings"`).

### 4. Industry Partition (`industry` / `selected_industry`)

- If omitted from the request, `industry` is hydrated from the deterministically selected or targeted service listing (`listing.industry_id`).
- If neither request nor listings specify an industry, fails with HTTP 422 (`"industry is required and could not be hydrated"`).

## Audit and Failure Isolation

- In accordance with M11.2 (#72), append-only audits are scheduled via FastAPI `BackgroundTasks` **only after** successful quote generation.
- If hydration fails at any step (missing mentor, inactive account, mismatched ownership, inactive listing, invalid country code, out-of-bounds text, or repository error), the request terminates immediately with the corresponding HTTP error code (401, 403, 422, or 503).
- **No audit document is ever created or persisted for failed or rejected requests.**
- When a listing is selected during hydration, its immutable document ID is recorded in `audit_payload["listing_id"]` alongside the verified `mentor_id` and token `auth_uid`.
