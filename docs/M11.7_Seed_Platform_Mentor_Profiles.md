# M11.7 Seed Repository Mentor Profiles from platform_mentor_corpus (#104, #172)

## Context & Motivation

Career Mentor OS connects to student pricing services via an automated adapter on `POST /price`. In compliance with contract `#99`, the platform issues a minimal payload containing only:
```json
{
  "mentorId": "p1"
}
```
accompanied by the `X-Platform-Key` header matching `PLATFORM_PRICE_KEY`.

In this contract, the pricing gateway does not receive raw inline strings (`raw_description`, `selected_industry`, `mentor_country`). Instead, the gateway resolves these features from the mentor's stored profile in the repository. If the repository does not contain the mentor's profile, the gateway fails with `422 Unprocessable Entity` naming the missing fields.

`src/data/seed_platform_mentors.py` bridges this persistence gap by loading ingested platform records from `data/processed/platform_mentor_corpus.parquet` (or `.csv`, or raw platform cache), mapping each record to a validated `ProfileDTO`, and seeding the profile directly into the repository (`InMemoryRepository` or `FirestoreRepository`).

## Schema Mapping

Each platform corpus record is mapped to the canonical `ProfileDTO`:

| Platform Corpus Field | ProfileDTO Attribute | Notes |
|-----------------------|----------------------|-------|
| `platform_mentor_profile_id` | `profile_id` | Primary document identifier (e.g. `p1`) |
| `platform_specialization` / `job_title` | `full_name` | Fallback: `Mentor {profile_id}` |
| synthesized internal email | `email` | e.g. `{profile_id}@platform.careermentor.internal` |
| `source_country` | `country_code` | Normalized to 2-letter uppercase ISO (`KE`) |
| `"active"` | `account_status` | Active profile status |
| `raw_description` | `metadata.raw_description` | Input to NLP text vectorizer / SVD |
| `industry_partition` | `metadata.selected_industry` | Selects the domain partition in KD-tree |
| `platform_mentor_user_id` | `metadata.platform_mentor_user_id` | Enables resolution by user ID |
| `listed_hourly_rate_kes` | `metadata.listed_hourly_rate_kes` | Sourced benchmark asking rate |
| `realised_hourly_rate_kes` | `metadata.realised_hourly_rate_kes` | Median realized booking rate |

### Identifier Aliasing

In Career Mentor OS, mentors possess both a `mentor_profile_id` (e.g. `p1`) and a `mentor_user_id` (e.g. `u1`). To ensure deterministic resolution regardless of which identifier the platform adapter supplies, the seeder:
1. Upserts the primary profile with `profile_id = record["platform_mentor_profile_id"]`.
2. Creates an alias profile under `profile_id = record["platform_mentor_user_id"]` with identical metadata.
3. Enhanced `_profile_for` in `src/engine/platform_price.py` matches against both `profile_id` and `metadata.platform_mentor_user_id`.

## Usage

### 1. Command Line Interface (CLI)

```bash
# Seed in-memory or inspect loaded records
python -m src.data.seed_platform_mentors --corpus data/processed/platform_mentor_corpus.parquet --json

# Seed from raw cached platform files
python -m src.data.seed_platform_mentors --corpus data/raw/career_mentor_os/
```

### 2. Runtime Auto-Seeding

Enable automatic seeding at server startup via environment variables:
```bash
export SEED_PLATFORM_MENTORS=true
export PLATFORM_MENTOR_CORPUS_PATH=data/processed/platform_mentor_corpus.parquet
```

### 3. Administrator Endpoint

An authorized operator can trigger re-seeding at runtime:
```bash
curl -X POST "http://localhost:8000/api/v1/admin/seed-platform-mentors" \
     -H "X-Admin-Token: $MLOPS_ADMIN_TOKEN"
```

## Verification

Comprehensive unit and integration coverage is in `tests/data/test_seed_platform_mentors.py`:
- Schema validation against `ProfileDTO`
- Multi-format ingestion (`.parquet`, `.csv`, raw directory fixtures)
- Resolution of `POST /price` using `platform_mentor_profile_id` (`p1`) and `platform_mentor_user_id` (`u1`)
- Error boundaries (422 with missing fields on unseeded IDs, 401/403 on admin endpoint)
