# M8.7 MLOps Operations for UC8–UC11

M8.7 makes the administrator use cases executable across the model and server
boundaries. It does not read service-account JSON and does not enable Firestore by
default in local development.

## Use-case mapping

| Use case | Server boundary | Model/operations implementation | Safeguard |
| --- | --- | --- | --- |
| UC8: manage Firebase repository and profiles | `GET/PUT/DELETE /api/v1/admin/profiles/*`, `GET /api/v1/admin/history` | `Repository`, `InMemoryRepository`, lazy `FirestoreRepository` | admin token, DTO validation, bounded history limit |
| UC9: monitor API/database latency | `GET /api/v1/admin/metrics`, `GET /health` | `MetricsRegistry` timers for API, inference, and database operations | no request payloads or credentials in metrics |
| UC10: trigger manual retraining | `POST /api/v1/admin/retrain`, `GET /api/v1/admin/retrain/{job_id}` | `MLOpsService.trigger_retrain()` calls the existing training evaluator | non-blocking lock, versioned artifact directory, atomic `active_model.json` publication |
| UC11: configure grid search | `GET/PUT /api/v1/admin/grid-search` | `GridSearchStore`, `MLOpsService.weighted_hybrid_coordinates()`, training evaluator arguments | Pydantic bounds, unique sorted `k_neighbors`, atomic JSON update |

## Authentication boundary

MLOps routes require the `X-Admin-Token` header and the server-side
`MLOPS_ADMIN_TOKEN` configuration (or an explicitly injected token in tests). The
value is compared in constant time and is never returned by health, metrics, or
error responses. Production deployments should replace this shared-token adapter
with Firebase verified admin claims when the Firebase Auth middleware is enabled.

## Firestore boundary

`FirestoreRepository` imports the Firebase Admin SDK lazily and calls
`firebase_admin.initialize_app()` with application-default credentials. Local tests
use `InMemoryRepository`; no credential path or credential contents are read by the
application code. Firestore collections align with the architecture schema:

- `mentors` for profiles;
- `historical_transactions` for pricing/audit records.

The repository interface keeps server logic independent of the persistence backend.

## Retraining publication

A retraining request:

1. obtains the process-local retraining lock;
2. creates `artifacts/versions/<timestamp>-<job-id>`;
3. invokes the existing `evaluate_and_serialize_training` pipeline using the active
   bounded configuration;
4. writes a manifest to a temporary file; and
5. atomically replaces `artifacts/active_model.json` only after the runner succeeds.

A failed run is marked `failed` and does not replace the active manifest. A second
concurrent request receives `busy`.

## Configuration example

```powershell
$env:MLOPS_ADMIN_TOKEN = "set-through-your-secret-manager"
$env:MLOPS_HARMONIZED_PARQUET = "C:\secure-data\harmonized_marketplace_corpus.parquet"
$env:MLOPS_MACRO_LOOKUP = "C:\secure-data\macro_lookup_table.json"
uvicorn src.serve:app --host 127.0.0.1 --port 8000
```

The input paths above are deployment configuration examples only; do not commit
local datasets, service-account files, or generated artifacts.

## Local API examples

```powershell
$headers = @{ "X-Admin-Token" = $env:MLOPS_ADMIN_TOKEN }
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/api/v1/admin/metrics -Headers $headers
Invoke-RestMethod http://127.0.0.1:8000/api/v1/admin/grid-search -Method Put -Headers $headers -ContentType "application/json" -Body '{"k_neighbors":[3,5,10,20],"text_weight":1.5,"metadata_weight":0.75}'
Invoke-RestMethod http://127.0.0.1:8000/api/v1/admin/retrain -Method Post -Headers $headers
```
