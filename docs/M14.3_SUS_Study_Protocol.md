# M14.3 System Usability Scale study protocol

**Status:** Protocol and response-scoring tool are prepared. No participant study has been run;
there is no measured SUS score in this repository, and the `>= 80` goal is not claimed as met.

## Study plan

- **Participants:** Recruit 10 adult users representative of technical mentors; record the number
  invited, consented, started, and completed. Report the actual sample size if recruitment falls
  short. Do not recruit minors or collect unnecessary demographic information.
- **Environment:** Use the native Android build connected to a dedicated staging Firebase project,
  test mentor profile, and synthetic listing data. Do not use real customer profiles or real pricing
  decisions. Record app commit/build, device model, Android version, and API region.
- **Consent and privacy:** Explain the task, voluntary nature, expected duration, data collected,
  retention period, and withdrawal process before starting. Obtain any institutional/organizational
  review required for the study. Do not record screens, audio, names, emails, account IDs, or free-form
  service descriptions. Use random `P001`-style study codes with no code-to-identity mapping in the
  response file. Store signed consent separately from responses under the approved access/retention
  policy; do not commit either to Git.
- **Facilitation:** Read the same neutral task instructions to each participant. Do not coach while a
  task is underway; record only anonymized task completion, recovery, and brief friction themes.
  Participants may stop at any time without consequence.
- **Tasks:** Sign in to the staging test account; enter a synthetic service description; select an
  industry and mentor/client countries; adjust competitiveness; request a quote; explain the
  recommended rate, fee-free negotiation corridor, M-Pesa fee, uncalibrated confidence disclosure,
  and comparable peers; then recover from one validation or simulated service error.
- **Questionnaire:** Immediately after the tasks, administer the original, unmodified 10-item SUS
  questionnaire using an authorized copy. This repository intentionally does not reproduce the
  questionnaire text. Collect one integer Likert response from 1 to 5 for each item; do not add
  leading questions to the score.

## Scoring and report

Keep a local CSV with exactly these headers and no additional columns:

```text
participant_id,item_1,item_2,item_3,item_4,item_5,item_6,item_7,item_8,item_9,item_10
```

Use only anonymous IDs such as `P001`; do not store names, email addresses, raw service descriptions,
or free-form identifying comments in this file. Score odd-numbered items as `response - 1`, even
items as `5 - response`, sum the adjusted values, and multiply by 2.5. The scoring script validates
all ten answers and outputs only sample size, mean, median, standard deviation, range, and whether
the mean meets 80:

```powershell
python scripts/analyze_sus_responses.py .\private-study\responses.csv
```

Do not commit the response CSV, consent records, or raw notes. Report study dates, recruitment and
completion counts, anonymized task success/recovery summaries, SUS mean/median/standard deviation
and range, accessibility setup, friction themes, and a remediation plan for any mean below 80.
Incomplete responses and deviations must be counted and explained rather than silently imputed.
