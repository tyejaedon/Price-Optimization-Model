# M14.2 authenticated mobile RTT protocol

**Status:** Measurement tooling and a reproducible protocol are prepared. No authenticated staging
environment or measurement result is available in this repository, so the `< 3.0 s` target is not
claimed as met.

## Fixed measurement profile

- **Client:** Pixel 2 Android Emulator, API 34 Google APIs image; record the emulator image/build,
  host OS, model, and Android version in the report.
- **Network:** Android Emulator `umts` speed preset (384 kbit/s up and down), `umts` delay preset
  (35–70 ms one-way), and **0% injected packet loss**. The stock emulator console exposes speed and
  delay but not packet loss; this baseline explicitly does not claim a lossy-radio measurement.
- **API:** HTTPS protected deployment in the intended staging region. Record the cloud region and
  client host/network location; both are currently unknown because no staging endpoint was supplied.
- **Samples:** 3 successful warm-ups followed by 30 sequential authenticated quote requests; no
  retries. Report p50 and p95, HTTP/timeout failure rate, Firebase token-refresh p50, server API
  p50, and server inference p50/p95 separately. The acceptance threshold is successful-request
  full-path p95 `< 3000 ms` with zero failed measured requests.
- **Timer boundary:** Full RTT starts before Firebase `getIdToken(forceRefresh = true)` and ends after
  the JSON quote response is read. This includes token refresh, DNS/TLS, request/response transfer,
  Firebase verification, mentor/Firestore authorization, inference and serialization. `Server-Timing`
  reports backend API and inference durations independently; audit persistence is asynchronous.

## Run on a signed-in staging emulator

Use a dedicated test Firebase account and an active test mentor profile owned by that account. Supply
Firebase client configuration through the existing Gradle properties/environment variables; never
commit the Firebase test password, ID token, service-account credentials, or participant data. Build
the live Retrofit client against the HTTPS staging origin using the properties documented in the
[Android app guide](Architecture/Android_App_Guide.md). Sign in through the app before starting the
measurement so the Firebase SDK has the test account's session.

With the emulator connected, set the radio profile and run the opt-in test:

```powershell
adb emu network speed umts
adb emu network delay umts
gradle :app:connectedDebugAndroidTest `
  -Pandroid.testInstrumentationRunnerArguments.rttMeasurementEnabled=true `
  -Pandroid.testInstrumentationRunnerArguments.mentorId=$env:PRICING_TEST_MENTOR_ID `
  -Pandroid.testInstrumentationRunnerArguments.apiRegion=$env:PRICING_TEST_API_REGION `
  -Pandroid.testInstrumentationRunnerArguments.sampleCount=30 `
  -Pandroid.testInstrumentationRunnerArguments.warmupCount=3
adb emu network speed full
adb emu network delay none
```

The test obtains a fresh ID token from the signed-in Firebase SDK for each request; no token is
passed on the command line or printed. The API base URL comes from the Android `PRICING_API_BASE_URL`
build configuration. It refuses non-HTTPS live URLs, requires a healthy Firestore-backed API, prints
one token-free `PRICING_RTT_REPORT` JSON record, and fails if any measured quote fails, inference
timing is absent, or full-path p95 is not below 3 seconds. The test is skipped unless explicitly
enabled, so CI never needs Firebase credentials or a staging API.

Store only the report and environment metadata (no tokens, account identifiers, raw request text,
or personal data) as evidence. A future loss-injection run must use a separately documented,
controlled network shaper; do not describe the 0%-loss baseline as representative of impaired
cellular coverage. Until a real staging run and report exist, keep issue #86 open.
